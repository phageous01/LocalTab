# LocalTab

[English](README.md) · [原创示例](examples/README.md) · [公开曲谱](https://github.com/phageous01/LocalTab-Scores)

LocalTab 是面向贝斯和吉他的本地 TAB 编辑器：编辑 MusicXML、把多个录音与乐谱对齐，
放慢播放来记谱和练习。乐谱、音频和同步点都保存在运行服务的电脑上，不依赖 Flat 账号或云服务。

**当前为 0.8.0 原型。** 软件界面以中文为主，同时提供中英文项目说明。

## 功能

- 四弦、五弦贝斯与六弦吉他，支持自定义调弦。
- 同时显示五线谱与带时值的 TAB，包括符干、符尾、连梁、附点和休止符。
- 在 TAB 上直接敲数字输入品位，同一音符位可输入多弦和弦。
- 时值、延音线、圆滑线、三连音、击弦、勾弦、滑音、推弦、死音、掌根闷音、力度、奏法与文字/音色标记。
- 增删小节，修改拍号和速度。
- 添加多个 MP3 并切换录音；每个录音独立同步，支持复制同步点。
- **0.50×–1.00× 播放，每次调整 0.01**，支持浏览器保持音高。
- 默认横向滚动，播放时随当前小节移动视图。
- 导入 MusicXML/MXL，导出 MusicXML，通过浏览器打印为 PDF。
- 本地自动保存、旧版本备份，以及局域网访问。
- 将 MusicXML 和自动生成的 PDF 一起发布到 GitHub 公开曲谱库。

## 安装与启动

服务端电脑需要 **Python 3.10 或以上版本**，客户端使用现代浏览器，主要面向 Chrome、Edge。
Node.js 只在运行 JavaScript 测试时需要。无需 npm install、编译、数据库或 CDN：
渲染库与字体已放在 `vendor/` 中，可以离线运行。

在 GitHub 点击 **Code → Download ZIP**，下载解压；或者使用 Git：

```sh
git clone https://github.com/phageous01/LocalTab.git
cd LocalTab
```

**Windows：** 双击 `Start.cmd`，或者在项目目录执行：

```powershell
py -3 server.py --open
```

`Start.cmd` 在有 Codex 自带 Python 时使用它，否则使用 Windows 的 `py -3` 启动器。
如果你的 Python 安装只提供 `python` 命令，也可运行 `python server.py --open`。

**macOS / Linux：**

```sh
python3 server.py --open
```

访问 [http://127.0.0.1:8767](http://127.0.0.1:8767)。使用期间保持终端运行；
在终端按 **Ctrl+C** 可停止服务。全新安装会打开新建乐谱窗口，
也可取消后导入仓库内的[原创示例](examples/README.md)。

### 局域网访问

默认监听 **0.0.0.0:8767，不需要登录**。能够连接到服务的设备都可查看和修改谱库。
同一局域网的其他电脑或平板访问 `http://<服务端电脑的局域网IP>:8767`；
启动时终端会打印可用地址。在服务端防火墙中允许 Python / TCP 8767 通过专用网络，
并使用完整的 `http://` 地址。

如果只想允许本机访问：

```sh
python server.py --host 127.0.0.1 --port 8767 --open
```

本原型用于可信任的局域网，没有面向公网的账号和权限系统。即使从另一台设备操作，
文件也保存在服务端电脑上。GitHub 用于存放代码和曲谱下载文件，不会运行这个 Python 服务。

## 完整使用流程：新建、同步、记谱

1. 点击 **＋ 新建**，输入标题、乐器、速度、拍号和小节数。
   速度单位为**四分音符/分钟**：例如 6/8、附点四分音符 = 80 时，输入 120。
   初始小节数为 1–200，速度为 20–300。也可以点击 **导入乐谱**，选择 `.musicxml`、`.xml` 或 `.mxl`。
2. 点击 **＋ 添加 MP3**，一次选择一个或多个文件。在 **音频来源** 中切换当前录音。
   多个录音是不同版本之间切换，不会混音同时播放。
3. 播放到一个清晰的小节起点并暂停，点击 **＋ 添加同步点**。
   小窗口会固定此刻的录音时间戳，输入它对应的小节，默认对齐该小节开头，再点 **保存同步点**。
   窗口打开后，改选小节不会把已经固定的录音时间改掉。
4. 在后面再加一个同步点；录音与谱面出现偏差的位置可以继续加点。
   点击时间线上的点可编辑，拖动可微调时间。展开 **同步点** 后可从其他录音复制节点，
   也可按毫秒整体平移。每个 MP3 分别校准，复制过来的节点可以作为起点。
5. 点击 TAB 音符位，按 **↑/↓** 选弦，直接敲品位数字。10–36 品请快速连续输入两位数字。
   输入和弦时保持当前音符位不变，换到其他弦继续输入；各弦共享同一时值。
   在工具栏中选择时值或奏法。
6. 按 **空格** 播放/暂停，在 **练习速度** 输入如 0.75。随时暂停修改，播放时横向视图跟随当前小节。
7. 等待保存状态显示完成，或点击 **保存**。修改会在短暂延迟后自动保存。
   下次打开会恢复录音和同步信息。**导出 MusicXML** 输出谱面；**打印 / PDF** 打开打印页，
   然后在浏览器打印窗口选择“另存为 PDF”。

### 快捷键和编辑工具栏

先点击 TAB 或工具栏使其获得焦点。时值修改提供“保护”和“替换”模式；
保护模式会阻止覆盖后续已有音符。

| 按键 | 功能 |
| --- | --- |
| `0`–`9` | 输入当前弦品位，快速连续输入组成两位数 |
| `↑` / `↓` | 选择弦 |
| `←` / `→`、`Enter` | 上一个 / 下一个音符位 |
| `Shift` + 点选 / 方向键 | 扩展选择范围 |
| `Alt+1` … `Alt+7` | 全音符、二分、四分、八分、十六分、三十二分、六十四分 |
| `.` / `Alt+T` | 附点 / 三连音 |
| `T` / `S` | 延音线 / 圆滑线 |
| `H` / `P` / `/` | 击弦 / 勾弦 / 滑音 |
| `X` | 当前弦死音 |
| `Delete` / `Backspace` | 删除当前弦音符，保留和弦其他音 |
| `R` | 整个音符位切换为休止符或音符 |
| `Alt+Enter` | 在当前小节后插入小节 |
| `空格` | 播放 / 暂停 |
| `Ctrl/Cmd+S` | 保存 |
| `Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z` | 撤销 / 重做 |

**小节 / Measures** 工具栏可修改拍号和速度。**文字 / 音色** 可写入 pick、clean 等谱面标记，
不会给录音应用音效。调弦从粗弦到细弦输入，如 `B0 E1 A1 D2 G2`，
并选择保持品位或保持实际音高。

## 同步算法

| 当前录音的同步点数量 | 光标如何移动 |
| --- | --- |
| 0 个 | 从音频 0 秒开始，按 MusicXML 的速度变化推进 |
| 1 个 | 用该点校准整体偏移，保留谱面的速度变化 |
| 2 个或更多 | 在相邻同步点之间按谱面理论时间插值，保留段内速度变化的比例 |

首个同步点之前、最后一个点之后，沿用邻近段的时间比例外推。
不会根据 MP3 总长度自动把全曲拉伸对齐。播放倍速影响媒体时间经过的快慢，
不改变已经保存的同步时间戳。有静音前奏时，可把第一个同步点设在 0 秒之后。

高级拍位从 **1** 开始，单位固定为**四分音符**，包括 6/8 拍；前进一个八分音符即加 0.5。
最后一个小节之后的小节开头表示乐谱结束。同步点在谱面位置与音频时间上都必须递增。

## 文件、备份和 GitHub

```text
LocalTab/
  public/                     浏览器界面、编辑模型和同步逻辑
  server.py                   Python 标准库 HTTP 服务
  examples/                   原创练习
  vendor/                     渲染库、字体和测试用 XML 依赖
  library/<project-id>/       自动创建；Git 默认忽略
    score.musicxml            乐谱
    project.json              录音引用和同步 metadata
    audio/*.mp3               导入的录音
  .local/backups/             之前保存的版本；Git 默认忽略
```

每个录音保存节点 `{ "q": ..., "seconds": ... }`，其中 `q` 是从谱面开始计算的四分音符数。
新保存的同步算法标记为 `tempo-map-v1`，音频文件通过项目文件夹内的相对路径引用。

请备份**整个 `library/` 文件夹**：单独导出的 MusicXML 不包含 MP3 和同步信息。
`.local/backups/` 保存之前的 XML/metadata 快照，不会复制 MP3。
多个窗口编辑不等于实时协作；检测到保存冲突时会拒绝覆盖，请先导出未保存的内容，再重新加载。

代码仓库忽略个人谱库、录音、日志及本地配置。公开 MusicXML 放在独立的
[LocalTab-Scores](https://github.com/phageous01/LocalTab-Scores)。点击 **发布 / Publish** 可发布到公开库，
普通“保存”仍**不会自动上传**。详见[发布设置与使用方式](docs/PUBLISHING.zh-CN.md)。

## 原型限制

- 编辑面向单乐器、单声部的 4–6 弦乐谱。复杂多乐器、声部交叠或不支持的 MusicXML 只读，
  谱面可能仅显示第一轨；请保留原始导入文件。
- 同一和弦各音共享时值，暂不支持不同弦同时演奏独立节奏的编辑。
- 多个 MP3 是录音版本切换，不是多轨混音。合成预览较基础，奏法标记不保证真实音色还原。
- 不同记谱软件对 MusicXML 标记的显示可能不同，PDF 排版依赖浏览器打印。
- 重复记号对应的完整音频导航、精细排版和协同编辑尚未完善；不是 Flat 全功能复刻。

## 开发与验证

在仓库根目录使用 Node.js 22+ 和 Python 3.10+ 运行：

```sh
node --test tests/*.test.mjs
python -m unittest discover -s tests -p "*_test.py"
```

macOS/Linux 可用 `python3`，Windows 可用 `py -3`。无需安装 npm 包。
测试涵盖记谱数据往返、和弦、奏法、小节结构、同步和 HTTP 行为，服务端测试使用隔离临时谱库。
详见[验证记录](VERIFICATION.md)。

测试样本使用合成数据，示例为原创练习。可通过 `python scripts/generate_examples.py` 重新生成。
